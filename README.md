# finalproject_Boyko_M26-555
## Описание проекта

ValutaTrade Hub — консольное приложение на Python для управления виртуальным валютным портфелем, выполнения операций покупки и продажи валют, а также получения актуальных обменных курсов из внешних API.

Проект разработан в рамках итоговой работы по программированию на Python и демонстрирует применение объектно-ориентированного программирования, модульной архитектуры, паттернов проектирования, работы с HTTP API, файлового хранения данных и обработки исключений.

## Установка и запуск

1. Клонирование репозитория
```
git clone <URL_РЕПОЗИТОРИЯ>
cd <ИМЯ_РЕПОЗИТОРИЯ>
```
2. Установка зависимостей

Для управления зависимостями используется uv.
```
uv sync
```
3. Запуск приложения

Запуск из корня проекта:
```
uv run python main.py
```
Либо через точку входа, определенную в pyproject.toml:
```
uv run valutatrade_hub
```
4. Сборка пакета

Для создания дистрибутива:
```
uv build
```
Для установки собранного пакета как CLI-инструмента:
```
uv tool install dist/*.whl
```
После установки приложение доступно через команду:
```
valutatrade_hub
```
5. Запуск линтера
С помощью ruff:
```
uv run ruff check .
```

## Использование

Приложение предоставляет интерактивный CLI, в котором команды вводятся последовательно.

### Регистрация

```
register --username alice --password 1234
```

Создает нового пользователя и пустой валютный портфель.

### Авторизация

```
login --username alice --password 1234
```

После успешной авторизации пользователь получает доступ к операциям со своим портфелем.

### Просмотр портфеля

```
show-portfolio --base USD
```

Показывает валютные балансы и их стоимость в выбранной базовой валюте.

### Покупка валюты

```
buy --currency BTC --amount 0.01
```

Добавляет указанное количество валюты в пользовательский кошелек с учетом бизнес-правил приложения.
Уменьшение долларового кошелька не предусмотрено.

### Продажа валюты

```
sell --currency BTC --amount 0.01
```
Уменьшает баланс соответствующего кошелька. При недостаточном количестве средств операция отклоняется.
Пополнение долларового кошелька не предусмотрено.

### Получение обменного курса

```
get-rate --from BTC --to USD
```
Возвращает курс указанной валютной пары. При необходимости используются механизмы обновления или кеширования курсов.

### Показ списка актуальных курсов валют с фильтрацией

```
show-rates --top N
```
Показывает N самых дорогих валют

```
show-rates --currency RUB
```
Показывает курс только для указанной валюты

### Обновление курсов

```
update-rates
```
Запускает обновление курсов через Parser Service.

Для выбора источника данных предусмотрен параметр --source, например:

```
update-rates --source coingecko
```
### Завершение работы

```
exit
```
В зависимости от режима выходит из личного кабинета пользователя или из программы вообще

## Применяемые принципы и паттерны

### Singleton

Применяется в SettingsLoader и DatabaseManager.

Обеспечивает использование единого экземпляра объекта для работы с конфигурацией и файловым хранилищем.

### Factory

Используется для создания объектов валют с учетом их типа.

Фиатные валюты и криптовалюты представлены отдельными классами с общим базовым интерфейсом.

Абстракция и полиморфизм

API-клиенты наследуются от BaseApiClient и предоставляют общий метод fetch_rates().

Это позволяет RatesUpdater работать с разными источниками данных через единый интерфейс.

### Инкапсуляция
В моделях используются методы и свойства для контролируемого изменения внутреннего состояния объектов.

### Декораторы

Декоратор log_action применяется для регистрации пользовательских операций без дублирования логики логирования в бизнес-методах.

### Кастомные исключения
Для обработки ошибок используется собственная иерархия исключений, включая:

* CurrencyNotFoundError — неизвестный код валюты.

* InsufficientFundsError — недостаточно средств для операции.

* ApiRequestError — ошибка получения данных из внешнего API.

### Кеширование валютных курсов и TTL

Для сокращения количества запросов к внешним API приложение использует локальный кеш валютных курсов, который хранится в `data/rates.json`.

Актуальность курсов определяется параметром `RATES_TTL_SECONDS` (Time To Live) — максимальным временем использования кешированных данных без обновления.

По умолчанию:

```
RATES_TTL_SECONDS = 300
```

При выполнении команды `get-rate` приложение:

1. Проверяет наличие валютной пары в локальном хранилище.
2. Проверяет время последнего обновления курса.
3. Если курс найден и его возраст не превышает TTL, использует сохраненное значение.
4. Если курс отсутствует или устарел, инициирует получение актуальных данных через Parser Service.
5. Сохраняет обновленные данные для дальнейшего использования.

Если внешний API недоступен, приложение обрабатывает ошибку запроса через `ApiRequestError`.

### Запуск Parser Service

Parser Service поддерживает два способа обновления:

#### Ручное обновление

Из интерактивного CLI:

```
update-rates
```

Для обновления через конкретный источник:

```
update-rates --source coingecko
```

#### Периодическое обновление

Для автоматического получения курсов используется класс `Scheduler`, который вызывает `RatesUpdater` с заданным интервалом.

Интервал обновления устанавливается в конфигурации Parser Service. Значение должно быть положительным.

При использовании планировщика обновления выполняются периодически без необходимости вручную вводить команду `update-rates`.

Периодический запуск обновлений зависит от подключения `Scheduler` к жизненному циклу приложения.

### Настройка API-ключей

Для получения актуальных курсов фиатных валют используется ExchangeRate API. Доступ к API настраивается через параметры Parser Service.

Рекомендуемый способ — использование файла `.env` в корне проекта.

Пример:

```
EXCHANGERATE_API_KEY=your_api_key_here
```

Для работы с переменными окружения используется библиотека `python-dotenv`.

Настройки URL, тайм-аутов и базовой валюты используются модулем `parser_service/config.py`.
